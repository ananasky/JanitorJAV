# JanitorJAV V1 产品与技术规格

状态：需求基线已确认  
目标平台：Windows + NVIDIA GPU  
文档范围：第一阶段，不包含业务代码实现

## 1. 产品目标

JanitorJAV V1 用于无人值守地全量扫描用户指定的 JAV 媒体库目录，通过固定时间点抽帧和本地 OCR，找出抽样画面中包含网址或 IP 地址的视频，并保留完整证据供人工审核。

系统还需分别标记短视频、RM/RMVB、VR、媒体探测失败、资产文件不完整等情况。所有自动判断只产生标签，不直接删除文件。用户确认后，系统只将文件移动到隔离区。

V1 面向约 9,600 个以上视频的媒体库，应支持长时间后台执行、分页审核、批量操作、中断续扫和 SMB 路径。

## 2. 范围边界

### 2.1 V1 包含

- 递归扫描选定媒体库目录。
- 发现、验证并分组视频及其 MDC 配套文件。
- 读取视频时长和分辨率。
- 按固定秒数与百分位抽帧。
- 使用本地、支持 NVIDIA CUDA 的 OCR 检测网址和 IPv4 地址。
- 保存全部抽样帧及 OCR 证据。
- 独立标签、筛选、排序、分页和批量审核。
- 将确认项移动到同级隔离目录。
- 从隔离区恢复。
- JSONL 任务记录、运行日志和断点续扫。
- Windows 本地完成通知。

### 2.2 V1 不包含

- 自动删除或永久删除媒体文件。
- 云端 OCR、云端视觉模型或外部模型接口。
- 基于赌场场景、博彩品牌或中文关键词的视觉语义判断。
- NFO 内容解析。
- 跨任务增量扫描或历史文件索引。
- 数据库。
- 图像增强、多版本预处理或多次 OCR。
- 损坏视频的完整解码检测、重复内容检测、字幕质量检查。
- Docker、WSL2、Windows 服务或开机自启动。
- 邮件、Webhook 等外部通知。

## 3. 运行与部署

- Windows 原生 Python 环境。
- 使用一键启动脚本启动本地后台服务和 Web 审核界面。
- Web 服务默认仅监听本机。
- 浏览器页面关闭不应影响后台任务。
- 启动时检查 Python 依赖、FFmpeg/ffprobe、OCR 模型和 CUDA 可用性。
- 列出可用 CUDA 设备，默认选择第一张，并允许在任务开始前选择 GPU。
- CUDA 初始化失败时明确提示；仅在用户选择后使用 CPU，不静默降级。
- 不随 Windows 开机启动。

## 4. 目录扫描

### 4.1 任务输入

每个任务由用户选择一个扫描根目录。每次任务都完整扫描，不复用历史任务结果。

媒体库可位于：

- Windows 本地盘；
- 映射网络盘；
- SMB UNC 路径，例如 `\\server\media\JAV`。

程序只使用 Windows 当前用户已建立的 SMB 登录会话，不保存 SMB 用户名或密码。

### 4.2 遍历规则

- 递归扫描全部真实子目录。
- 不跟随符号链接、目录联接或 `.lnk` 快捷方式。
- 任何直接包含视频文件的目录都视为资产目录，即使它同时包含子目录。
- 存在视频的目录继续递归扫描其子目录。
- 先按可配置扩展名白名单筛选，再用 ffprobe 验证视频流。

默认视频扩展名至少包含：

`mp4`、`mkv`、`avi`、`mov`、`wmv`、`m4v`、`ts`、`mts`、`m2ts`、`webm`、`flv`、`mpg`、`mpeg`、`rm`、`rmvb`。

### 4.3 网络错误

- SMB 文件读取失败时自动重试 3 次。
- 仍失败则记录独立错误标签并继续扫描其他文件。
- 任务完成后支持仅重试失败项。
- 单个网络错误不得终止整个任务。

## 5. 资产发现与分组

### 5.1 标准资产组

一个标准资产组包含：

- 1 个视频；
- `<视频主文件名>.nfo`；
- `<视频主文件名>-poster.jpg`；
- `<视频主文件名>-fanart.jpg`；
- `<视频主文件名>-thumb.jpg`；
- 可选字幕。

字幕仅按以下两类严格形式关联：

- `<视频主文件名>.<字幕扩展名>`；
- `<视频主文件名>.AI.<字幕扩展名>`。

字幕扩展名至少支持 `srt`、`ass`、`ssa`、`vtt`、`sub`。扩展名比较大小写不敏感。

### 5.2 不完整资产组

视频缺少 NFO 或任意标准图片时仍需正常扫描，并建立不完整资产组。每个缺失项独立标记，例如：

- `missing_nfo`
- `missing_poster`
- `missing_fanart`
- `missing_thumb`

不完整资产组不算目录内的标准完整资产组。

### 5.3 CD 分组

- 由连字符分隔、大小写不敏感的 `CD数字` 标记表示分段，例如 `-CD1`、`-cd02`。
- CD 标记可以位于文件主名中的任意连字符分段位置。
- 解析时移除 CD 和 VR 标记，以剩余主名作为分组键。
- 同组任一 CD 分段命中规则时，整套 CD 共同带标、审核、隔离和恢复。
- 每个 CD 分段先关联自己的 NFO、图片和字幕。
- 不带 CD 标记的多个视频分别组成独立资产组。

### 5.4 VR 分组

- 由连字符分隔、大小写不敏感的独立 `VR` 标记表示 VR 视频。
- VR 标记可位于文件主名任意连字符分段位置，也可在 CD 标记之前或之后。
- 任一 CD 分段带 VR 标记时，整套按 VR 处理。
- 其他分段未带 VR 时添加 `inconsistent_vr_naming`。
- VR 资产仍读取元数据并检查配套文件，但跳过抽帧、OCR 和短于 3 分钟规则。

## 6. 媒体元数据

每个视频至少记录：

- 文件路径；
- 文件大小；
- 修改时间；
- 视频时长；
- 视频宽度和高度；
- 视频格式；
- 所属资产组及 CD/VR 属性。

元数据无法读取时分别添加 `duration_unknown`、`resolution_unknown` 或相应探测错误标签。

审核界面支持：

- 按时长最小值和最大值筛选、排序；
- 按宽度和高度范围筛选；
- 按低于 480p、480p、720p、1080p、1440p、2160p 及以上筛选；
- 分辨率档位以短边为主要判定依据；
- CD 套装显示各分段时长和分辨率，并显示合计时长。

## 7. 抽帧规则

非 VR 视频使用以下候选点位：

- 固定秒数：5、10、15、20、25 秒；
- 视频时长百分位：10%、25%、50%、75%、90%。

处理规则：

- 超出或落在视频有效结尾之外的点位丢弃。
- 相差不超过 0.5 秒的点位合并，只抽取一帧。
- 合并后的帧记录全部原始点位来源。
- 每个视频最多产生 10 张证据帧，短视频可少于 10 张。
- 只对原始抽帧执行一次 OCR。
- V1 不做放大、对比度增强或其他预处理。
- 全部实际抽取的帧均保存为任务证据。

## 8. OCR 与网址识别

### 8.1 OCR

- OCR 完全在本机运行。
- 技术方案需支持 Windows + NVIDIA CUDA，并保留 CPU 兼容路径。
- V1 不调用视觉模型或远程接口。
- OCR 对任务中的帧使用 GPU 批处理队列。

具体 OCR 框架和版本应在技术验证阶段根据 Windows/CUDA 兼容性和真实样本确定；PaddleOCR 可作为优先候选，但不在需求基线中锁死版本。

### 8.2 点分文本规则

只要 OCR 文本出现符合“主体`.`后缀”的点分结构，即视为网址候选：

- 不要求 `http://`、`https://` 或 `www`。
- 不依赖已知顶级域名白名单。
- 后缀最短允许 2 个字符。
- IPv4 地址也算命中。
- 识别前归一化全角句点和点号周围的空格。
- 保留 OCR 原文、归一化文本和实际命中片段。

### 8.3 证据等级

- 高置信度候选：`url_detected`。
- 低置信度候选：`possible_url_detected`。
- IPv4 另外添加 `ip_address_detected`。
- 任意一张抽样帧命中即可给资产组打标。
- 视频级证据分取最强单帧证据，不要求连续帧或多帧重复。
- CD 套装需记录具体由哪个分段、哪个时间点触发。
- 置信度阈值可配置，默认值由真实样本验证后确定。

## 9. 独立标签模型

标签彼此独立，同一资产组可同时拥有多个标签。至少包括：

- `url_detected`
- `possible_url_detected`
- `ip_address_detected`
- `duration_under_3m`
- `legacy_format_rm`
- `legacy_format_rmvb`
- `vr_video`
- `inconsistent_vr_naming`
- `probe_failed`
- `decode_failed`
- `frame_extract_failed`
- `ocr_failed`
- `network_read_failed`
- `duration_unknown`
- `resolution_unknown`
- `missing_nfo`
- `missing_poster`
- `missing_fanart`
- `missing_thumb`
- `source_changed_since_scan`
- `quarantine_failed`
- `quarantine_file_conflict`

短于 3 分钟的非 VR 视频无条件添加 `duration_under_3m`，但仍抽帧和 OCR。

RM/RMVB 无条件添加对应旧格式标签，同时继续尝试元数据探测、抽帧和 OCR；实际失败时叠加具体错误标签。

## 10. 目录完整性与剩余内容

### 10.1 系统杂项忽略列表

默认忽略以下内容：

- `.DS_Store`
- `Thumbs.db`
- `desktop.ini`
- `._*`
- `.Spotlight-V100`
- `.Trashes`
- `.fseventsd`
- `System Volume Information`
- `$RECYCLE.BIN`

忽略列表可在配置文件中扩展。忽略只影响目录是否实际为空以及剩余内容统计；整体隔离目录时这些内容仍一起移动。

### 10.2 动态目录判断

目录级判断基于用户的“准备隔离”选择动态计算：

- 若目录内仍有未选择隔离的资产组，目录不能视为空。
- 若所有完整和不完整资产组都准备隔离，且仅剩系统杂项，则添加 `folder_effectively_empty` 提示。
- 若仍有非系统文件或额外子目录，则给目录添加提示并列出剩余内容、子目录名称和文件数量。
- 用户可选择只隔离已选资产组，或额外确认整体隔离目录。
- 整体隔离会移动目录内所有内容，包括系统杂项、未归属文件和额外子目录。

## 11. Web 审核界面

### 11.1 列表

- 默认只显示至少有一个标签的审核单元。
- 可切换显示全部已扫描资产组。
- CD 套装只占一条记录；无 CD 视频各占一条记录。
- 服务端分页，默认每页 50 条，可切换 25、50、100。
- 支持当前页全选。
- 支持按标签、格式、状态、目录、置信度、时长和分辨率筛选。
- 支持相应字段排序。
- 支持批量设置“确认保留”或“准备隔离”。
- 执行隔离前展示资产组数、文件数、目录影响和目标路径汇总。

### 11.2 文件与证据查看

- 列表不直接加载图片或视频。
- 每条记录列出全部抽帧的本地证据链接。
- 点击后在浮窗中按需加载图片，并可前后切换该视频的全部帧。
- 浮窗支持在浏览器新标签页打开图片。
- 浮窗显示时间点、OCR 原文、归一化文本、置信度、网址/IP 命中内容和证据等级。
- 每条记录只提供最终层资产目录地址。
- 点击目录地址后，用 Windows 资源管理器打开该目录。
- 不需要为视频、NFO、字幕和原始 JPG 分别提供打开链接。
- 后端只允许访问当前任务扫描根、证据目录和隔离目录中的已知路径。

### 11.3 审核状态

- `pending`：待审核
- `keep`：确认保留
- `ready_to_quarantine`：准备隔离
- `quarantined`：已隔离
- `quarantine_failed`：隔离失败
- `restored`：已恢复

## 12. 隔离区

### 12.1 路径规则

隔离根固定命名为 `JanitorJAV_Quarantine`。

它必须：

- 位于扫描根目录的直接父目录下；
- 与扫描根目录互为同级目录；
- 不存在，或已经存在但为空；
- 可由当前 Windows 用户写入。

示例：

- 扫描根：`\\server\media\JAV`
- 源目录：`\\server\media\JAV\2026\ABC-123`
- 隔离根：`\\server\media\JanitorJAV_Quarantine`
- 目标目录：`\\server\media\JanitorJAV_Quarantine\2026\ABC-123`

程序可自动创建隔离根，并借此验证写权限。如果隔离根非空，禁止开始新任务。

任务完成后，由用户人工检查并移走、改名或清空隔离根。程序不自动清理隔离内容。

### 12.2 移动语义

- 仅允许同父目录下的移动，不实现跨盘或跨共享复制删除。
- 保留相对于扫描根的全部目录结构。
- 同一任务内可逐层创建或复用目标子目录。
- 正常情况下不应发生文件名冲突。
- 异常同名文件不得静默覆盖；冲突时保留源文件并记录错误。

### 12.3 事务与安全

- 隔离前重新校验资产文件清单、大小和修改时间。
- 任何源文件新增、缺失或变化时添加 `source_changed_since_scan`，停止该审核单元的隔离。
- 资产组和整套 CD 以审核单元为事务边界。
- 移动前检查所有源文件和目标路径。
- 任一文件失败时尝试回滚本次已经移动的文件。
- 只有整个审核单元全部成功后才标记为已隔离。
- 整体目录隔离以完整目录为操作单元。
- 所有文件操作逐项写入审计日志。

### 12.4 恢复

- 根据任务日志按审核单元恢复。
- 资产组、CD 套装和整体目录均可恢复。
- 恢复到原始相对路径。
- 目标存在冲突时停止，不覆盖。
- 恢复成功后状态改为 `restored`。

## 13. 任务、日志与证据

### 13.1 工作目录

默认工作目录：

`%LOCALAPPDATA%\JanitorJAV\tasks\<任务ID>\`

工作目录可配置，但不得写入媒体库内部。

建议任务目录结构：

```text
<task-id>/
  task.json
  events.jsonl
  assets.jsonl
  operations.jsonl
  runtime.log
  evidence/
    <asset-id>/
      <video-id>/
        <frame-id>.jpg
```

### 13.2 记录要求

- `task.json`：任务配置、路径、创建时间、状态、并发和 GPU 配置。
- `events.jsonl`：任务状态变化、暂停、继续、取消和异常事件。
- `assets.jsonl`：资产组、视频元数据、标签、OCR 和审核状态快照或事件。
- `operations.jsonl`：隔离、回滚、恢复及逐文件结果。
- `runtime.log`：人类可读的运行与排错日志。
- `evidence`：全部实际抽取的证据帧。

日志不得包含 SMB 认证信息。

### 13.3 恢复与清理

- 每完成一个视频或资产组立即追加记录。
- 程序重启后可载入未完成任务并继续尚未完成的审核单元。
- 新建任务仍从头完整扫描，不复用旧任务记录。
- 历史任务显示创建时间、状态和磁盘占用。
- 不自动过期删除任务或证据。
- 用户可手动删除任务记录及证据；该操作不得影响媒体库或隔离区。

## 14. 任务控制和进度

界面至少显示：

- 已发现视频数；
- 已完成数与总数；
- 当前处理文件；
- 带标签资产组数；
- 异常数；
- 当前吞吐量；
- 已运行时间和预计剩余时间。

任务支持：

- 暂停；
- 继续；
- 安全取消；
- 同任务断点续扫；
- 仅重试失败项。

取消或退出时先安全写入当前进度。任务完成后显示摘要并发送 Windows 系统通知。

## 15. 并发与性能

- 提供保守、平衡、高性能和自定义并发模式。
- 默认使用平衡模式。
- ffprobe 和 FFmpeg 抽帧可并行。
- OCR 使用单独的 GPU 批处理队列。
- 并发配置在任务开始前确定，任务进行中不切换。
- 默认策略需兼顾 SMB 吞吐和 GPU 利用率，避免大量随机网络读取。
- 分页和图片按需加载必须保证 9,600+ 视频规模下页面可用。

## 16. 测试与人工评估

### 16.1 样本标注工具

验证阶段允许用户提供多个任意结构的测试目录。目录结构本身不代表正确结果。

提供轻量标注页面，将样本标为：

- 应命中；
- 不应命中；
- 不确定。

标注结果保存为独立 JSONL 基准文件。

### 16.2 评测输出

- 根据“视频任意位置是否存在网址”建立人工真值。
- 漏检拆分为：
  - `sampling_miss`：固定抽样点未覆盖网址；
  - `ocr_miss`：抽样帧已包含网址但 OCR 未识别。
- 输出命中、漏检、误报和不确定清单及相关证据。
- V1 不设硬性召回率或误报率验收门槛。
- 最终效果由用户人工评估，并据具体问题调整抽帧、OCR 或阈值。

## 18. 页面流程

```text
启动检查
  -> 新建任务
  -> 选择扫描根
  -> 自动确定并校验空隔离区
  -> 选择 GPU 和并发档位
  -> 开始扫描
  -> 查看进度 / 暂停 / 继续 / 取消
  -> 扫描完成摘要
  -> 筛选和分页审核
  -> 确认保留 / 准备隔离
  -> 动态计算目录影响
  -> 汇总确认
  -> 执行隔离
  -> 查看结果 / 失败重试 / 恢复
```

## 19. 分阶段实施计划

### 阶段 A：技术验证

- 验证 Windows 原生环境中的 ffprobe 和精确抽帧。
- 验证候选 OCR 框架的 CUDA 安装、GPU 选择和 CPU 回退。
- 使用少量真实帧验证点分文本与 IPv4 检测。
- 验证 SMB UNC 路径读取、同级目录移动和资源管理器打开。
- 固化支持的 Python、CUDA、OCR 和 FFmpeg 版本组合。

### 阶段 B：扫描核心

- 实现目录遍历和视频验证。
- 实现资产、CD、VR、字幕和配套文件分组。
- 实现元数据探测、抽帧、OCR、网址匹配和标签。
- 实现 JSONL 任务记录和证据目录。
- 实现失败重试和任务内断点续扫。

### 阶段 C：审核界面

- 实现任务创建和路径校验。
- 实现进度页、分页列表、筛选、排序和批量审核。
- 实现按需帧预览、OCR 依据展示和资源管理器打开。
- 实现动态目录影响提示。

### 阶段 D：隔离与恢复

- 实现源文件变化校验。
- 实现资产组、CD 套装和整体目录的事务式移动。
- 实现失败回滚、操作审计和恢复。
- 实现隔离区为空、同父目录和权限校验。

### 阶段 E：验证与打磨

- 实现测试样本标注页面和评测报告。
- 使用用户样本调整 OCR 置信度阈值。
- 验证 9,600+ 视频规模下的内存、页面和日志性能。
- 验证 SMB 中断、文件变化、程序退出和恢复场景。
- 完善一键启动脚本、环境检查和 Windows 通知。
